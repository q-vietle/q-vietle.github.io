Indexes: finding rows fast

Why some queries read a whole table and others jump straight to the answer.

In short

  • Without an index, the database must read the whole table to find matching rows: a full (sequential) scan.
  • An index is a separate, sorted structure (usually a B-tree) that leads straight to the rows, like the index at the back of a book.
  • The planner decides whether to use it. Functions on the column, patterns starting with % and conditions matching a large share of rows prevent or discourage it. Every index also slows down writes a little.

SQL · Phần C · Bài 13/14

Index: tìm hàng nhanh

Vì sao có query phải đọc cả bảng còn có query nhảy thẳng tới câu trả lời.

Tóm tắt

  • Không có index, database phải đọc cả bảng để tìm các hàng khớp: quét toàn bảng (sequential scan).
  • Một index là một cấu trúc riêng, đã sắp xếp (thường là B-tree), dẫn thẳng tới các hàng, giống như mục lục tra cứu ở cuối sách.
  • Planner quyết định có dùng nó hay không. Hàm áp lên cột, mẫu bắt đầu bằng % và điều kiện khớp một tỉ lệ lớn các hàng sẽ cản trở hoặc làm nản việc dùng index. Mỗi index cũng làm thao tác ghi chậm đi một chút.

A book with and without an index

To find "B-tree" in a book without an index you read every page. With an index you look it up in sorted order and jump to the right page.

A table is stored in pages (blocks of a few kilobytes, about 100 rows each here). A full scan reads them all. A B-tree index is sorted and very wide: each node points to hundreds of children, so even a billion rows need only four or five steps from the top to the bottom. Change the table size and the query:

Một cuốn sách có và không có mục lục

Để tìm "B-tree" trong một cuốn sách không có mục lục, bạn đọc từng trang. Có mục lục, bạn tra theo thứ tự rồi nhảy tới đúng trang.

Một bảng được lưu trong các trang (page; các khối vài kilobyte, ở đây khoảng 100 hàng mỗi trang). Quét toàn bảng đọc tất cả. Một index B-tree được sắp xếp và rất rộng: mỗi nút trỏ tới hàng trăm nút con, nên ngay cả một tỉ hàng cũng chỉ cần bốn năm bước từ đỉnh xuống đáy. Hãy đổi kích thước bảng và query:

Creating and checking an index

CREATE INDEX users_email_idx ON users (email);

EXPLAIN SELECT * FROM users WHERE email = 'lan.tran@example.com';
--  Index Scan using users_email_idx on users ...

CREATE INDEX users_email_lower_idx ON users (LOWER(email));   -- for LOWER(email) = ...

EXPLAIN shows the plan the database chose without running the query. Use it when a query is slow: "Seq Scan" on a big table with a selective condition usually means a missing or unusable index.

  • Index columns that you search, join or sort on often, and that pick out few rows.
  • Do not index everything: each INSERT, UPDATE and DELETE must also update every index, and indexes take disk space.
  • Primary keys and UNIQUE columns get an index automatically.
Going further: why is the tree so shallow?

If each node holds about 300 keys, one level reaches 300 rows, two levels 90,000, three levels 27 million and four levels 8 billion. The number of steps grows with the logarithm of the table size, while a full scan grows in step with it.

Tạo và kiểm tra một index

CREATE INDEX users_email_idx ON users (email);

EXPLAIN SELECT * FROM users WHERE email = 'lan.tran@example.com';
--  Index Scan using users_email_idx on users ...

CREATE INDEX users_email_lower_idx ON users (LOWER(email));   -- cho LOWER(email) = ...

EXPLAIN cho thấy kế hoạch mà database đã chọn mà không chạy query. Hãy dùng nó khi một query chậm: "Seq Scan" trên một bảng lớn với điều kiện chọn lọc thường nghĩa là thiếu index hoặc index không dùng được.

  • Đánh index cho các cột bạn thường tìm kiếm, join hoặc sắp xếp, và chọn ra ít hàng.
  • Đừng đánh index mọi thứ: mỗi INSERT, UPDATE và DELETE cũng phải cập nhật mọi index, và index tốn dung lượng đĩa.
  • Khoá chính và các cột UNIQUE được tự động tạo index.
Đi sâu hơn: vì sao cây lại nông đến vậy?

Nếu mỗi nút chứa khoảng 300 khoá, một tầng với tới 300 hàng, hai tầng 90,000, ba tầng 27 triệu và bốn tầng 8 tỉ. Số bước tăng theo logarit của kích thước bảng, trong khi quét toàn bảng tăng theo tỉ lệ thuận.
