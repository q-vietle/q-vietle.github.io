What is a database?

Tables, rows, columns and keys: the few ideas that everything else in SQL builds on.

In short

  • A relational database stores data in tables. Each row is one record (one customer) and each column is one attribute (their city).
  • Every column has a data type (number, text, date). A missing value is written NULL.
  • A primary key identifies each row. A foreign key points to a row in another table, and this is how tables are connected.

Database là gì?

Bảng, hàng, cột và khoá: vài ý tưởng mà mọi thứ khác trong SQL đều dựa vào.

Tóm tắt

  • Một relational database (cơ sở dữ liệu quan hệ) lưu dữ liệu trong các bảng. Mỗi hàng là một bản ghi (một khách hàng) và mỗi cột là một thuộc tính (thành phố của họ).
  • Mỗi cột có một kiểu dữ liệu (số, văn bản, ngày). Giá trị bị thiếu được viết là NULL.
  • Khoá chính (primary key) xác định từng hàng. Khoá ngoại (foreign key) trỏ tới một hàng trong bảng khác, và đó là cách các bảng được nối với nhau.

Database, table, SQL

A database is a program that stores data safely and answers questions about it. SQL is the language you use to ask.

A spreadsheet is fine for one person and a few thousand rows. A database is built for much more: millions of rows, many users at the same time, rules that the data must follow, and answers in milliseconds. You talk to it in SQL (Structured Query Language). The popular databases, PostgreSQL, MySQL, SQLite, SQL Server and Oracle, all speak SQL with only small differences.

Inside a relational database, data lives in tables. Every note in this series uses the same two small tables from an imaginary shop: customers and orders. Switch the mode below and hover the tables.

Database, bảng, SQL

Database là một chương trình lưu dữ liệu an toàn và trả lời các câu hỏi về dữ liệu đó. SQL là ngôn ngữ để bạn đặt câu hỏi.

Bảng tính (spreadsheet) ổn cho một người và vài nghìn dòng. Database được xây cho nhiều hơn thế: hàng triệu hàng, nhiều người dùng cùng lúc, các quy tắc mà dữ liệu bắt buộc phải tuân theo, và câu trả lời trong vài mili giây. Bạn nói chuyện với nó bằng SQL (Structured Query Language). Các database phổ biến như PostgreSQL, MySQL, SQLite, SQL Server và Oracle đều dùng SQL, chỉ khác nhau đôi chút.

Bên trong một database quan hệ, dữ liệu nằm trong các bảng. Mọi bài trong loạt này đều dùng cùng hai bảng nhỏ của một cửa hàng tưởng tượng: customers và orders. Hãy đổi chế độ bên dưới và rê chuột lên các bảng.

Keys connect the tables

An order does not repeat the customer's name and city. It stores only customer_id, a pointer to one row of customers.

  • Primary key (customer_id, order_id): a column whose value is different in every row and never NULL. It is the row's identity.
  • Foreign key (orders.customer_id): a column that holds the primary key of a row in another table. The database can check that it always points to a customer that exists.

Tables are created with CREATE TABLE, which lists every column, its type and its rules:

CREATE TABLE customers (
  customer_id INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,        -- must always have a value
  city        TEXT,                 -- may be NULL
  joined      INTEGER
);

CREATE TABLE orders (
  order_id    INTEGER PRIMARY KEY,
  customer_id INTEGER REFERENCES customers (customer_id),   -- foreign key
  product     TEXT,
  category    TEXT,
  amount      NUMERIC,
  order_date  DATE
);

Two details of this data matter later: Emma's city is NULL (unknown), and order 111 has no customer (a guest checkout). Real data always has gaps like these, and SQL has rules for them.

Going further: why not keep everything in one big table?

If every order also stored the customer's city, changing one customer's city would mean updating many rows, and missing one would leave the data contradicting itself. Splitting data so each fact is stored once is called normalisation. JOINs (note 10) put the pieces back together when you need them.

Khoá nối các bảng với nhau

Một đơn hàng không lặp lại tên và thành phố của khách. Nó chỉ lưu customer_id, một con trỏ tới một hàng của customers.

  • Khoá chính (customer_id, order_id): một cột có giá trị khác nhau ở mọi hàng và không bao giờ NULL. Đó là danh tính của hàng.
  • Khoá ngoại (orders.customer_id): một cột chứa khoá chính của một hàng trong bảng khác. Database có thể kiểm tra rằng nó luôn trỏ tới một khách hàng có thật.

Bảng được tạo bằng CREATE TABLE, liệt kê mọi cột, kiểu và quy tắc của chúng:

CREATE TABLE customers (
  customer_id INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,        -- luôn phải có giá trị
  city        TEXT,                 -- có thể là NULL
  joined      INTEGER
);

CREATE TABLE orders (
  order_id    INTEGER PRIMARY KEY,
  customer_id INTEGER REFERENCES customers (customer_id),   -- khoá ngoại
  product     TEXT,
  category    TEXT,
  amount      NUMERIC,
  order_date  DATE
);

Hai chi tiết của dữ liệu này sẽ quan trọng về sau: city của Emma là NULL (không biết), và đơn hàng 111 không có khách hàng (khách mua không đăng nhập). Dữ liệu thật luôn có những chỗ trống như vậy, và SQL có quy tắc để xử lý chúng.

Đi sâu hơn: sao không để tất cả trong một bảng lớn?

Nếu mỗi đơn hàng cũng lưu thành phố của khách, thì đổi thành phố của một khách nghĩa là phải sửa nhiều hàng, và sót một hàng sẽ khiến dữ liệu tự mâu thuẫn. Việc tách dữ liệu để mỗi sự kiện chỉ được lưu một lần gọi là chuẩn hoá (normalisation). JOIN (bài 10) ghép các mảnh lại khi bạn cần.
