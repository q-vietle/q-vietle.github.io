Window functions

Rankings, running totals and comparisons with the previous row, without collapsing rows.

In short

  • A window function computes a value for each row from a set of related rows (its window). Unlike GROUP BY, no rows are merged.
  • PARTITION BY splits the rows into windows; ORDER BY inside OVER (…) orders the rows within each window.
  • Common uses: ranking (ROW_NUMBER, RANK), running totals (SUM(…) OVER) and the previous row (LAG).

SQL · Phần C · Bài 12/14

Window function

Xếp hạng, tổng luỹ kế và so sánh với hàng trước, mà không gộp các hàng lại.

Tóm tắt

  • Một window function tính một giá trị cho mỗi hàng từ một tập các hàng liên quan (cửa sổ của nó). Khác với GROUP BY, không có hàng nào bị gộp.
  • PARTITION BY chia các hàng thành các cửa sổ; ORDER BY bên trong OVER (…) sắp thứ tự các hàng trong mỗi cửa sổ.
  • Dùng phổ biến: xếp hạng (ROW_NUMBER, RANK), tổng luỹ kế (SUM(…) OVER) và hàng trước đó (LAG).

GROUP BY merges, a window keeps

SELECT order_id, category, amount,
       SUM(amount) OVER (PARTITION BY category) AS category_total
FROM orders;

Every order stays in the result, and each one gets the total of its own category next to it. That is impossible with GROUP BY, which would return one row per category.

Try the functions below. Click a row to outline the rows its value is computed from.

GROUP BY gộp lại, window thì giữ nguyên

SELECT order_id, category, amount,
       SUM(amount) OVER (PARTITION BY category) AS category_total
FROM orders;

Mọi đơn đều ở lại trong kết quả, và mỗi đơn được kèm tổng của category của nó. Điều đó bất khả thi với GROUP BY, vì nó chỉ trả về một hàng cho mỗi category.

Hãy thử các hàm bên dưới. Bấm vào một hàng để khoanh những hàng dùng để tính giá trị của nó.

A classic: the top row of each group

WITH ranked AS (
  SELECT order_id, category, product, amount,
         ROW_NUMBER() OVER (PARTITION BY category
                            ORDER BY amount DESC NULLS LAST) AS rn
  FROM orders
)
SELECT category, product, amount
FROM ranked
WHERE rn = 1;          -- the biggest order of each category

Window functions run after WHERE (note 9), so you cannot write WHERE ROW_NUMBER() … = 1 directly. Compute the number in a CTE, then filter it.

Going further: the frame

With ORDER BY, an aggregate such as SUM uses a frame that, by default, runs from the first row of the partition up to the current row and its ties. You can set it yourself: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW gives a moving sum over three rows.

Một bài kinh điển: hàng đầu của mỗi nhóm

WITH ranked AS (
  SELECT order_id, category, product, amount,
         ROW_NUMBER() OVER (PARTITION BY category
                            ORDER BY amount DESC NULLS LAST) AS rn
  FROM orders
)
SELECT category, product, amount
FROM ranked
WHERE rn = 1;          -- đơn lớn nhất của mỗi category

Window function chạy sau WHERE (bài 9), nên bạn không thể viết trực tiếp WHERE ROW_NUMBER() … = 1. Hãy tính số thứ tự trong một CTE, rồi lọc nó.

Đi sâu hơn: frame

Với ORDER BY, một hàm tổng hợp như SUM dùng một frame mà theo mặc định chạy từ hàng đầu tiên của partition đến hàng hiện tại và các hàng bằng nó. Bạn có thể tự đặt: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW cho tổng trượt trên ba hàng.
