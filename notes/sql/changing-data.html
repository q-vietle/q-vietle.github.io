Changing data: INSERT, UPDATE, DELETE

Adding, changing and removing rows, and the one mistake everybody makes once.

In short

  • INSERT adds rows, UPDATE changes values in existing rows and DELETE removes rows.
  • UPDATE and DELETE choose their rows with WHERE, exactly like SELECT. Without WHERE, every row is affected.
  • The database enforces the table's rules: a duplicate primary key or a missing required value is rejected, and nothing changes.

SQL · Phần A · Bài 6/14

Thay đổi dữ liệu: INSERT, UPDATE, DELETE

Thêm, sửa và xoá hàng, và lỗi mà ai cũng mắc một lần.

Tóm tắt

  • INSERT thêm hàng, UPDATE đổi giá trị trong các hàng đã có và DELETE xoá hàng.
  • UPDATE và DELETE chọn hàng bằng WHERE, y như SELECT. Không có WHERE thì mọi hàng đều bị tác động.
  • Database thực thi các quy tắc của bảng: trùng khoá chính hoặc thiếu giá trị bắt buộc sẽ bị từ chối và không có gì thay đổi.

Three statements

INSERT INTO customers (customer_id, name, city, joined)
VALUES (7, 'Lan', 'Hanoi', 2024);

UPDATE customers
SET city = 'Hanoi'
WHERE customer_id = 5;

DELETE FROM customers
WHERE customer_id = 6;

UPDATE and DELETE work in two steps: first WHERE finds the rows, then the change is applied to exactly those rows.

The database answers with how many rows were affected, for example UPDATE 1. Run the statements below on a live copy of the table. Try running the INSERT twice.

Ba câu lệnh

INSERT INTO customers (customer_id, name, city, joined)
VALUES (7, 'Lan', 'Hanoi', 2024);

UPDATE customers
SET city = 'Hanoi'
WHERE customer_id = 5;

DELETE FROM customers
WHERE customer_id = 6;

UPDATE và DELETE làm việc theo hai bước: trước hết WHERE tìm các hàng, rồi thay đổi được áp dụng đúng cho những hàng đó.

Database trả lời bằng số hàng bị tác động, ví dụ UPDATE 1. Hãy chạy các câu lệnh bên dưới trên một bản sao trực tiếp của bảng. Thử chạy INSERT hai lần xem.

Safe habits

  • Before an UPDATE or DELETE, run a SELECT with the same WHERE and check that it returns the rows you expect.
  • Change rows by their primary key when you can (WHERE customer_id = 5): it can only ever match one row.
  • Work inside a transaction, so a mistake can still be undone with ROLLBACK (note 14).
Going further: deleting a customer who has orders

If orders point to customer 1 through a foreign key, the database refuses to delete that customer, because the orders would point to nothing. You can choose other behaviour when creating the table, such as ON DELETE CASCADE (delete the orders too) or ON DELETE SET NULL.

Thói quen an toàn

  • Trước khi UPDATE hoặc DELETE, hãy chạy một SELECT với cùng WHERE và kiểm tra nó trả về đúng những hàng bạn mong đợi.
  • Thay đổi hàng theo khoá chính khi có thể (WHERE customer_id = 5): nó chỉ có thể khớp tối đa một hàng.
  • Làm việc trong một transaction, để một sai lầm vẫn có thể được hoàn tác bằng ROLLBACK (bài 14).
Đi sâu hơn: xoá một khách hàng đang có đơn

Nếu các đơn hàng trỏ tới khách 1 qua khoá ngoại, database sẽ từ chối xoá khách đó, vì các đơn sẽ trỏ vào hư không. Bạn có thể chọn hành vi khác khi tạo bảng, như ON DELETE CASCADE (xoá luôn các đơn) hoặc ON DELETE SET NULL.
