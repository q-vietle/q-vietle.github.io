How a query really runs

The order the database follows is not the order you write, and that explains many error messages.

In short

  • You write SELECT first, but the database starts with FROM.
  • The logical order is FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
  • Each step only sees what earlier steps produced. That is why a column alias works in ORDER BY but not in WHERE.

SQL · Phần B · Bài 9/14

Một query thực sự chạy như thế nào

Thứ tự database thực hiện không phải thứ tự bạn viết, và điều đó giải thích nhiều thông báo lỗi.

Tóm tắt

  • Bạn viết SELECT trước, nhưng database bắt đầu với FROM.
  • Thứ tự logic là FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
  • Mỗi bước chỉ thấy những gì các bước trước tạo ra. Vì vậy alias của cột dùng được trong ORDER BY nhưng không dùng được trong WHERE.

Written order vs running order

Read a query like a recipe in this order: take the rows (FROM), throw some away (WHERE), sort them into groups (GROUP BY), throw some groups away (HAVING), compute the output columns (SELECT), sort (ORDER BY), cut (LIMIT).

Step through one query that uses every clause. The highlighted clause is the one running, and the table shows what it produces.

Thứ tự viết và thứ tự chạy

Hãy đọc một query như một công thức nấu ăn theo thứ tự này: lấy các hàng (FROM), bỏ bớt một số (WHERE), chia thành nhóm (GROUP BY), bỏ bớt một số nhóm (HAVING), tính các cột đầu ra (SELECT), sắp xếp (ORDER BY), cắt (LIMIT).

Hãy đi từng bước qua một query dùng mọi mệnh đề. Mệnh đề được tô sáng là mệnh đề đang chạy, và bảng cho thấy nó tạo ra gì.

Errors this order explains

SELECT category, SUM(amount) AS revenue
FROM orders
WHERE revenue > 100          -- ERROR: column "revenue" does not exist
GROUP BY category;

WHERE runs before SELECT, so the alias revenue does not exist yet. The fix is to filter the groups with HAVING SUM(amount) > 100. For the same reason an aggregate is never allowed in WHERE, while ORDER BY, which runs after SELECT, can use aliases freely.

Going further: logical order, not physical order

This is the order in which the meaning of a query is defined. The database's optimiser is free to do the work differently (for example, use an index to read only the matching rows) as long as the result is the same as if it had followed these steps. DISTINCT runs right after SELECT, and window functions (note 12) run after HAVING and before ORDER BY.

Những lỗi mà thứ tự này giải thích

SELECT category, SUM(amount) AS revenue
FROM orders
WHERE revenue > 100          -- LỖI: cột "revenue" không tồn tại
GROUP BY category;

WHERE chạy trước SELECT, nên alias revenue chưa tồn tại. Cách sửa là lọc các nhóm bằng HAVING SUM(amount) > 100. Cũng vì lý do đó, hàm tổng hợp không bao giờ được phép nằm trong WHERE, còn ORDER BY, chạy sau SELECT, thì dùng alias thoải mái.

Đi sâu hơn: thứ tự logic, không phải thứ tự vật lý

Đây là thứ tự định nghĩa ý nghĩa của một query. Bộ tối ưu (optimiser) của database được tự do làm việc theo cách khác (ví dụ dùng index để chỉ đọc các hàng khớp) miễn là kết quả giống như khi nó làm theo các bước này. DISTINCT chạy ngay sau SELECT, và các window function (bài 12) chạy sau HAVING và trước ORDER BY.
