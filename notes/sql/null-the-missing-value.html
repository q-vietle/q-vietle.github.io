NULL: the missing value

Why a missing value makes comparisons answer "unknown", and how to handle it safely.

In short

  • NULL means the value is missing or unknown. It is not 0 and not an empty text.
  • Any comparison with NULL gives UNKNOWN, a third truth value. WHERE keeps only TRUE, so UNKNOWN rows disappear.
  • Test for missing values with IS NULL / IS NOT NULL, and replace them with COALESCE.

NULL: giá trị bị thiếu

Vì sao giá trị thiếu khiến phép so sánh trả lời "không biết", và cách xử lý an toàn.

Tóm tắt

  • NULL nghĩa là giá trị bị thiếu hoặc chưa biết. Nó không phải 0 và cũng không phải chuỗi rỗng.
  • Mọi phép so sánh với NULL cho ra UNKNOWN, một giá trị đúng/sai thứ ba. WHERE chỉ giữ TRUE, nên các hàng UNKNOWN biến mất.
  • Kiểm tra giá trị thiếu bằng IS NULL / IS NOT NULL, và thay thế chúng bằng COALESCE.

Three truth values

Is Emma's city HCMC? We do not know her city, so the honest answer is neither yes nor no: it is UNKNOWN.

SQL uses three truth values: TRUE, FALSE and UNKNOWN. NULL = 5, NULL <> 5 and even NULL = NULL are all UNKNOWN. AND, OR and NOT follow the rules below: an UNKNOWN only matters when the other side does not already decide the answer.

Ba giá trị đúng/sai

Thành phố của Emma có phải HCMC không? Ta không biết thành phố của cô ấy, nên câu trả lời trung thực không phải có cũng không phải không: nó là UNKNOWN.

SQL dùng ba giá trị đúng/sai: TRUE, FALSE và UNKNOWN. NULL = 5, NULL <> 5 và thậm chí NULL = NULL đều là UNKNOWN. AND, OR và NOT tuân theo các quy tắc bên dưới: một UNKNOWN chỉ có ý nghĩa khi vế còn lại chưa quyết định được kết quả.

NULL in WHERE

WHERE keeps a row only when the condition is TRUE. FALSE and UNKNOWN are both thrown away.

So a row with a NULL can vanish from both a query and its opposite. Try the cases below, especially city = NULL, which never returns anything.

NULL trong WHERE

WHERE chỉ giữ một hàng khi điều kiện là TRUE. FALSE và UNKNOWN đều bị bỏ đi.

Vì vậy một hàng chứa NULL có thể biến mất khỏi cả một query lẫn query đối lập của nó. Hãy thử các trường hợp bên dưới, đặc biệt là city = NULL, không bao giờ trả về gì.

Working with NULL

SELECT name FROM customers WHERE city IS NULL;        -- missing city

SELECT name, COALESCE(city, 'unknown') AS city   -- first non-NULL value
FROM customers;

SELECT product, amount * 1.1 FROM orders;       -- NULL * 1.1 is NULL

COALESCE(a, b, …) returns the first value that is not NULL, which is handy for display. Arithmetic with NULL gives NULL: an unknown number times 1.1 is still unknown.

Going further: NULL shows up again later

Aggregates such as SUM and AVG skip NULLs (note 7), GROUP BY puts all NULLs in one group (note 8), a NULL key never matches in a JOIN (note 10), and NOT IN with a NULL in the list returns nothing at all (note 11).

Làm việc với NULL

SELECT name FROM customers WHERE city IS NULL;        -- thành phố bị thiếu

SELECT name, COALESCE(city, 'unknown') AS city   -- giá trị đầu tiên không phải NULL
FROM customers;

SELECT product, amount * 1.1 FROM orders;       -- NULL * 1.1 vẫn là NULL

COALESCE(a, b, …) trả về giá trị đầu tiên không phải NULL, tiện để hiển thị. Phép tính với NULL cho ra NULL: một con số chưa biết nhân với 1.1 vẫn là chưa biết.

Đi sâu hơn: NULL còn xuất hiện lại ở phần sau

Các hàm tổng hợp như SUM và AVG bỏ qua NULL (bài 7), GROUP BY gom mọi NULL vào một nhóm (bài 8), khoá NULL không bao giờ khớp trong JOIN (bài 10), và NOT IN với một NULL trong danh sách thì không trả về gì cả (bài 11).
